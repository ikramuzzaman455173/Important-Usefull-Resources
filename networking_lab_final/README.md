## 1. নেটওয়ার্ক আর্কিটেকচার ও আইপি প্ল্যান

### 🔹 ডিভাইস ও ক্যাবলিং
- **ডিভাইস:** 1টি Cisco 2911 Router, 3টি 2960 Switches, 9টি PCs (প্রতি সুইচে ৩টি পিসি)।
- **ক্যাবল:** ভিন্ন লেয়ারের ডিভাইস হওয়ায় সব সংযোগে **Copper Straight-Through** তার ব্যবহার করা হয়েছে।
  ```text
  Router (G0/0) ──► Switch 1 (F0/1) ──► PC 0, PC 1, PC 2
  Router (G0/1) ──► Switch 2 (F0/1) ──► PC 3, PC 4, PC 5
  Router (G0/2) ──► Switch 3 (F0/1) ──► PC 6, PC 7, PC 8
  ```

### 🔹 আইপি প্ল্যান টেবিল

| সুইচ / LAN | রাউটার পোর্ট | ডিফল্ট গেটওয়ে (Router IP) | সাবনেট মাস্ক | সাবনেট নেটওয়ার্ক | DHCP আইপি রেঞ্জ (পিসির জন্য) |
|---|---|---|---|---|---|
| **Switch 1** | GigabitEthernet 0/0 | `192.168.10.1` | `255.255.255.0` | `192.168.10.0/24` | `192.168.10.2` – `192.168.10.254` |

| **Switch 3** | GigabitEthernet 0/2 | `192.168.30.1` | `255.255.255.0` | `192.168.30.0/24` | `192.168.30.2` – `192.168.30.254` |

## 2. রাউটার কনফিগারেশন (Router Configuration)

**Router → CLI** ওপেন করুন। `Router>` দেখতে পেলে নিচের ধাপগুলো অনুসরণ করুন:

### ২.১ ইন্টারফেস কনফিগারেশন (Interface Setup)
> রাউটারের ৩টি পোর্টে ৩টি সুইচের গেটওয়ে আইপি অ্যাসাইন করা এবং পোর্টগুলো চালু করা।

```text
enable
configure terminal
no ip domain-lookup
interface gigabitEthernet 0/0
ip address 192.168.10.1 255.255.255.0
no shutdown
exit
interface gigabitEthernet 0/1
ip address 192.168.20.1 255.255.255.0
no shutdown
exit
interface gigabitEthernet 0/2
ip address 192.168.30.1 255.255.255.0
no shutdown
exit
```

**💡 কমান্ডের সহজ ব্যাখ্যা:**
- `enable` ➔ প্রিভিলেজড মোডে (`Router#`) ঢোকা।
- `configure terminal` ➔ গ্লোবাল কনফিগারেশন মোডে (`Router(config)#`) যাওয়া।
- `no ip domain-lookup` ➔ কোনো কমান্ড ভুল টাইপ করলেও রাউটার যেন DNS খুঁজতে গিয়ে হ্যাং না হয়।
- `interface gigabitEthernet 0/0` ➔ নির্দিষ্ট ইন্টারফেস নির্বাচন করা।
- `ip address <IP> <Subnet Mask>` ➔ পোর্টের নিজস্ব আইপি ও সাবনেট মাস্ক সেট করা।
- `no shutdown` ➔ পোর্টটিকে সচল (UP) করা (রাউটার পোর্ট ডিফল্ট বন্ধ থাকে)।
- `exit` ➔ ইন্টারফেস মোড থেকে বের হওয়া।

---

### ২.২ DHCP পুল কনফিগারেশন (DHCP Setup)
> পিসিগুলোতে যেন অটোমেটিক আইপি বরাদ্দ পায়, সেজন্য ৩টি সুইচের জন্য ৩টি DHCP পুল তৈরি করা।

```text
ip dhcp excluded-address 192.168.10.1
ip dhcp excluded-address 192.168.20.1
ip dhcp excluded-address 192.168.30.1
ip dhcp pool SWITCH1
network 192.168.10.0 255.255.255.0
default-router 192.168.10.1
dns-server 8.8.8.8
exit
ip dhcp pool SWITCH2
network 192.168.20.0 255.255.255.0
default-router 192.168.20.1
dns-server 8.8.8.8
exit
ip dhcp pool SWITCH3
network 192.168.30.0 255.255.255.0
default-router 192.168.30.1
dns-server 8.8.8.8
exit
```

**💡 কমান্ডের সহজ ব্যাখ্যা:**
- `ip dhcp excluded-address <IP>` ➔ রাউটারের গেটওয়ে আইপিগুলো বাদ রাখা (যাতে আইপি কনফ্লিক্ট না হয়)।
- `ip dhcp pool <NAME>` ➔ প্রতিটি সুইচের জন্য আলাদা নামের পুল তৈরি করা।
- `network <IP> <Mask>` ➔ কোন সাবনেট থেকে পিসিগুলোকে আইপি দেওয়া হবে তা ঠিক করা।
- `default-router <IP>` ➔ পিসিগুলোর জন্য ডিফল্ট গেটওয়ে ঠিক করা।
- `dns-server 8.8.8.8` ➔ ইন্টারনেট নেম রেজোলিউশনের জন্য DNS আইপি দেওয়া।

---

### ২.৩ কনফিগারেশন সেভ করা (Save Config)
> RAM (running-config) থেকে কনফিগারেশন স্থায়ী মেমোরি NVRAM (startup-config) এ এক ক্লিকে সেভ করা।

```text
end
write
```
*(💡 **টিপ:** `write` কমান্ড দিলে কোনো বাড়তি কনফার্মেশন প্রম্পট ছাড়াই সরাসরি `[OK]` দিয়ে সেভ হয়ে যায়। যদি ল্যাব ম্যানুয়ালের মতো `copy running-config startup-config` দেন, তবে প্রম্পট আসলে কিবোর্ডে **Enter** চাপতে হবে)*

---

## 4. পিং ও কানেক্টিভিটি টেস্ট (Ping Test)

Switch 1 এর **PC 0** ওপেন করুন ➔ **Desktop** ➔ **Command Prompt** এ গিয়ে লিখুন:

```text
ping 192.168.20.2
ping 192.168.30.2
```

> **📌 গুরুত্বপূর্ণ নোট:** প্রথমবার পিং করার সময় ১ম প্যাকেটটি `Request timed out` হতে পারে। এর কারণ হলো **ARP (Address Resolution Protocol)** ব্রডকাস্ট চালিয়ে MAC Address খুঁজতে সামান্য সময় নেয়। এরপর থেকে সবগুলো প্যাকেটে `Reply from ...` আসবে।

## 5. 🔄 সেটআপ রিসেট ও পুনরায় প্র্যাকটিস (Reset Commands)

ল্যাব পরীক্ষা দেওয়ার আগে বারবার হাতেনাতে প্র্যাকটিস করতে রাউটার ক্লিয়ার করার উপায়:

### উপায় ১: ফ্যাক্টরি রিসেট ও রিলোড (সঠিক ২-ধাপ পদ্ধতি)

> ⚠️ **মনে রাখবেন:** `erase startup-config` দেওয়ার পর রাউটার নিশ্চিত হওয়ার জন্য একটি `[confirm]` প্রম্পট দেয়। তাই একসাথে সব না দিয়ে নিচের মতো ২ ধাপে দিন:

#### ধাপ ১: সেভ কনফিগ ডিলিট করা
```text
enable
erase startup-config
```
👉 CLI-তে `[confirm]` আসবে ➔ কিবোর্ডে **Enter** চাপুন।

#### ধাপ ২: রাউটার রিবুট করা
```text
reload
```
- যদি আসে `System configuration has been modified. Save? [yes/no]:` ➔ **`no`** লিখে **Enter** দিন। *(ভুল করেও yes দিবেন না)*
- এরপর `Proceed with reload? [confirm]` আসলে ➔ **Enter** চাপুন।
- রিবুট শেষে `initial configuration dialog? [yes/no]:` আসলে ➔ **`no`** লিখে **Enter** দিন।

---

### উপায় ২: রিবুট ছাড়া এক ক্লিকে সরাসরি সব মুছে ফেলা (Fastest)
*কোনো প্রম্পট বা রিবুট ছাড়া তাৎক্ষণিকভাবে সম্পূর্ণ কনফিগারেশন খালি করতে এই পুরো ব্লকটি পেস্ট করুন:*

```text
enable
configure terminal
no ip dhcp pool SWITCH1
no ip dhcp pool SWITCH2
no ip dhcp pool SWITCH3
no ip dhcp excluded-address 192.168.10.1
no ip dhcp excluded-address 192.168.20.1
no ip dhcp excluded-address 192.168.30.1
default interface gigabitEthernet 0/0
default interface gigabitEthernet 0/1
default interface gigabitEthernet 0/2
end
write
```

### ৫.৩ পিসির আইপি ক্লিয়ার করার নিয়ম (PC IP Clear)

প্যাকেট ট্রেসারে পিসি তার শেষ পাওয়া আইপি মেমোরিতে (Cache) রেখে দেয়। রাউটার ক্লিয়ার করার পর পিসির আইপি শূন্য বা রিসেট করার উপায়:

- **পদ্ধতি ১ (সবচেয়ে দ্রুত — Command Prompt):**
  - পিসির **Desktop → Command Prompt** এ যান এবং লিখুন:
    ```text
    ipconfig /release
    ```
    👉 সাথে সাথে আইপি রিলিজ হয়ে `0.0.0.0` হয়ে যাবে!
  - নতুন কনফিগারেশন করার পর নতুন আইপি নিতে চাইলে লিখবেন: `ipconfig /renew` (বা GUI থেকে DHCP সিলেক্ট করবেন)।

- **পদ্ধতি ২ (GUI থেকে):**
  - **Desktop → IP Configuration** এ গিয়ে একবার **Static** এ ক্লিক করুন, তারপর আবার **DHCP** তে চাপুন।
  - যেহেতু রাউটারে কোনো DHCP নেই, তাই ৪-৫ সেকেন্ড পর দেখাবে: `DHCP failed. APIPA is being used (169.254.x.x)` — অর্থাৎ আগের আইপি আর নেই।

## 6. 🎯 ল্যাব ফাইনাল ও ভাইভা প্রশ্নোত্তর (Viva Q&A)

### ৬.১ টপোলজি ও ডিভাইস
> **প্রশ্ন ১: এই ল্যাবে রাউটার এবং সুইচের কাজ কী? শুধু সুইচ দিয়ে কি কাজ হতো?**
>
> **উত্তর:**
> - **সুইচ (Layer 2):** একই সাবনেটের ভেতরের পিসিগুলোকে পরস্পরের সাথে কানেক্ট করে (যেমন Switch 1 এর ৩টি পিসি)।
> - **রাউটার (Layer 3):** ৩টি ভিন্ন সাবনেট (`10.0`, `20.0`, `30.0`) এর মধ্যে ইন্টার-নেটওয়ার্ক রাউটিং করায়।
> - **শুধু সুইচ দিয়ে হতো না:** কারণ সুইচ ব্রডকাস্ট ডোমেন ভাঙতে পারে না এবং ভিন্ন সাবনেটে প্যাকেট পাঠাতে লেয়ার ৩ রাউটিং ডিভাইস আবশ্যক।

> **প্রশ্ন ২: কোন ক্যাবল ব্যবহার করা হয়েছে এবং কেন?**
>
> **উত্তর:** Router to Switch এবং Switch to PC উভয় ক্ষেত্রে **Copper Straight-Through** ক্যাবল ব্যবহার করা হয়েছে, কারণ এরা ভিন্ন লেয়ারের বা ভিন্ন ধরণের ডিভাইস।

> **প্রশ্ন ৩: রাউটার পোর্টে `no shutdown` কমান্ড কেন দেওয়া হয়?**
>
> **উত্তর:** সিসকো রাউটারের ইন্টারফেস ডিফল্ট অবস্থায় `administratively down` (বন্ধ) থাকে। পোর্ট সচল (UP) করার জন্য `no shutdown` কমান্ড দিতে হয়।

---

### ৬.২ আইপি প্ল্যান ও সাবনেটিং
> **প্রশ্ন ৪: `/24` সাবনেট মাস্কে (`255.255.255.0`) কতটি ভ্যালিড আইপি পাওয়া যায়?**
>
> **উত্তর:**
> - মোট আইপি সংখ্যা: $2^8 = 256$ টি।
> - ব্যবহারযোগ্য (Usable Host) আইপি: $256 - 2 = 254$ টি (`.1` থেকে `.254`)।
> - বাদ পড়া ২টি আইপি: প্রথম আইপি (`.0`) = Network ID, এবং শেষ আইপি (`.255`) = Broadcast ID।

> **প্রশ্ন ৫: Default Gateway কী এবং এর কাজ কী?**
>
> **উত্তর:** ডিফল্ট গেটওয়ে হলো লোকাল নেটওয়ার্ক থেকে বাইরের যেকোনো নেটওয়ার্কে যাওয়ার প্রবেশদ্বার (এক্ষেত্রে রাউটারের নিজ নিজ পোর্টের আইপি, যেমন `192.168.10.1`)। পিসি যখন অন্য সাবনেটে ডেটা পাঠাতে চায়, সে প্যাকেটটি সরাসরি ডিফল্ট গেটওয়েতে পাঠিয়ে দেয়।

---

### ৬.৩ DHCP ও DORA প্রসেস
> **প্রশ্ন ৬: DHCP কী এবং এটি কীভাবে কাজ করে? DORA প্রসেস কী?**
>
> **উত্তর:** DHCP = **Dynamic Host Configuration Protocol**। এটি স্বয়ংক্রিয়ভাবে পিসিগুলোকে আইপি দেয়। এটি **DORA** প্রক্রিয়ায় কাজ করে:
> 1. **D (Discover):** পিসি নেটওয়ার্কে ব্রডকাস্ট করে DHCP সার্ভার খোঁজে।
> 2. **O (Offer):** DHCP সার্ভার পিসিকে একটি অব্যবহৃত আইপি অফার করে।
> 3. **R (Request):** পিসি সার্ভারকে জানায় যে সে ওই আইপিটি নিতে চায়।
> 4. **A (Acknowledge):** সার্ভার নিশ্চিত করে আইপিটি পিসিকে লিজ (Lease) দেয়।

> **প্রশ্ন ৭: `ip dhcp excluded-address` কেন দেওয়া হয়?**
>
> **উত্তর:** ডিফল্ট গেটওয়ে আইপি (যেমন `192.168.10.1`) রাউটারে ফিক্সড করা থাকে। DHCP যাতে ভুল করে এই আইপিটি অন্য কোনো সাধারণ পিসিকে না দিয়ে দেয় (IP Conflict প্রতিরোধে), সেজন্য গেটওয়ে আইপি এক্সক্লুড করা হয়।

---

### ৬.৪ রাউটিং ও ট্রাবলশুটিং
> **প্রশ্ন ৮: কোনো রাউটিং প্রটোকল (যেমন RIP/OSPF) ছাড়াই এক সুইচের পিসি থেকে অন্য সুইচের পিসিতে Ping পায় কেন?**
>
> **উত্তর:** কারণ ৩টি নেটওয়ার্কই (`10.0`, `20.0`, `30.0`) একই রাউটারের ৩টি ইন্টারফেসে সরাসরি যুক্ত (**Directly Connected**)। রাউটার তার সরাসরি কানেক্টেড সাবনেটগুলো স্বয়ংক্রিয়ভাবে রাউটিং টেবিলে অ্যাড করে নেয় (কোড `C` = Connected)।

> **প্রশ্ন ৯: প্রথমবার Ping করলে ১ম প্যাকেট "Request Timed Out" হওয়ার কারণ কী?**
>
> **উত্তর:** প্রথমবার প্যাকেট পাঠানোর সময় গন্তব্যের MAC Address জানা থাকে না। তাই **ARP (Address Resolution Protocol)** ব্রডকাস্ট চালিয়ে MAC Address সংগ্রহ করতে সামান্য সময় লাগে, ফলে প্রথম প্যাকেট ড্রপ হতে পারে। এরপর থেকে ১০০% সফল হয়।

---

### ৬.৫ জরুরি ভেরিফিকেশন ও Show কমান্ডস

Privileged EXEC মোডে (`Router#`) এই কমান্ডগুলো দিয়ে শিক্ষককে যেকোনো রেজাল্ট দেখানো যাবে:

| কমান্ড | কী কাজ করে / আউটপুট |
|---|---|
| `show ip interface brief` | রাউটারের সব ইন্টারফেসের আইপি ও পোর্ট UP আছে কিনা তা দেখতে। |
| `show ip route` | রাউটারের রাউটিং টেবিল ও সরাসরি কানেক্টেড নেটওয়ার্কগুলো দেখতে। |
| `show ip dhcp binding` | কোন পিসি কোন আইপি পেয়েছে তার ম্যাক অ্যাড্রেস ও আইপি তালিকা দেখতে। |
| `show ip dhcp pool` | প্রতিটি DHCP পুলে মোট কতটি আইপি ব্যবহৃত হচ্ছে তা দেখতে। |
| `show running-config` | রাউটারে বর্তমানে চালু থাকা পুরো কনফিগারেশন চেক করতে। |

> **প্রশ্ন ১০: `running-config` এবং `startup-config` এর মধ্যে পার্থক্য কী?**
>
> **উত্তর:**
> - `running-config` থাকে রাউটারের **RAM**-এ (অস্থায়ী, রিস্টার্ট দিলে মুছে যায়)।
> - `startup-config` থাকে **NVRAM**-এ (স্থায়ী, রিস্টার্ট দিলেও সংরক্ষিত থাকে)।
> - তাই কাজ শেষে `copy running-config startup-config` বা `write` দিয়ে সেভ করতে হয়।

## 7. 💡 অতিরিক্ত দরকারি কমান্ড ও কিবোর্ড শর্টকাট (Optional & Shortcuts)

ল্যাবে স্যার যদি কোনো অতিরিক্ত টাস্ক দেন বা দ্রুত কাজ করার দরকার হয়, তখন এই কমান্ড ও শর্টকাটগুলো সাহায্য করবে:

### ৭.১ অতিরিক্ত দরকারি CLI কমান্ডসমূহ

| কমান্ড | মোড | কাজ / বিবরণ |
|---|---|---|
| `hostname NUB-Router` | `Router(config)#` | রাউটারের নাম পরিবর্তন করা। |
| `enable secret cisco` | `Router(config)#` | প্রিভিলেজড মোডে ঢোকার জন্য এনক্রিপ্টেড পাসওয়ার্ড সেট করা। |
| `banner motd # Authorized Access Only #` | `Router(config)#` | রাউটারে প্রবেশের সময় ওয়েলকাম/সিকিউরিটি ব্যানার মেসেজ দেখানো। |
| `description Connected to Switch 1` | `Router(config-if)#` | ইন্টারফেসে বিবরণ বা লেবেল যুক্ত করা। |
| `clear ip dhcp binding *` | `Router#` | রাউটারের সব DHCP আইপি লিজ একসাথে মুছে ফেলা। |
| `show mac address-table` | `Switch#` | সুইচের কোন পোর্টে কোন পিসির MAC যুক্ত আছে তা দেখা। |
| `ipconfig /all` | `PC Command Prompt` | পিসির IP, Gateway, DNS এবং Physical (MAC) Address এক নজরে দেখা। |
| `arp -a` | `PC Command Prompt` | পিসি কার কার IP ও MAC চিনে রেখেছে (ARP Table) তা দেখা। |
| `tracert 192.168.20.2` | `PC Command Prompt` | প্যাকেট কোন কোন হপ/গেটওয়ে দিয়ে অপর পিসিতে যাচ্ছে তা ট্রেস করা। |

### ৭.২ ল্যাব পরীক্ষার জন্য প্রয়োজনীয় কিবোর্ড শর্টকাট (Cisco CLI & Packet Tracer)

| কিবোর্ড শর্টকাট | কাজ / ব্যবহার |
|---|---|
| **`Ctrl` + `Shift` + `6`** | **Emergency Break:** কোনো ভুল টাইপ করে রাউটার ডোমেইন লুকআপে হ্যাং হলে তাৎক্ষণিকভাবে ছাড়িয়ে আনা। |
| **`Tab`** | **Auto-Complete:** কমান্ডের অর্ধেক লিখে Tab চাপলে স্বয়ংক্রিয়ভাবে পুরো কমান্ড পূরণ হয়ে যায় (যেমন `conf` লিখে Tab দিলে `configure`)। |
| **`?` (Help)** | কমান্ডের যেকোনো স্থানে `?` চাপলে পরবর্তী সম্ভাব্য কমান্ডগুলোর তালিকা দেখায়। |
| **`Up (↑)` / `Down (↓)` Arrow** | পূর্বে দেওয়া কমান্ডগুলো দ্রুত ফিরিয়ে আনা (Command History)। |
| **`Ctrl` + `Z`** অথবা **`Ctrl` + `C`** | যেকোনো কনফিগারেশন সাব-মোড থেকে সরাসরি Privileged EXEC মোডে (`#`) ফিরে আসা। |
| **`Alt` + `Shift` + `D`** (বা `>>` বাটন) | **Fast Forward Time:** প্যাকেট ট্রেসারে সময় দ্রুত এগিয়ে নিয়ে কমলা পোর্টগুলোকে দ্রুত সবুজ করা। |
| **`Esc`** | প্যাকেট ট্রেসারে সিলেক্ট করা ক্যাবল বা টুল ক্যানসেল করা। |
